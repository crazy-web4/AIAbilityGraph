# 5.2 AI 产品设计

> AI 产品设计需要平衡技术能力与用户体验，本章讲解 AI 原生产品的设计原则与方法。

## 学习目标

- [ ] 理解 AI 产品与传统产品的差异
- [ ] 掌握 AI 产品的设计原则
- [ ] 学会处理 AI 产品的不确定性
- [ ] 设计有效的用户反馈机制

## 5.2.1 AI 产品设计原则

### 1. 管理期望

AI 产品必须帮助用户理解：
- 系统能做什么
- 系统不能做什么
- 系统在什么情况下可能出错

```
设计模式：能力说明

┌─────────────────────────────────────────┐
│  我是你的 AI 写作助手                     │
│                                         │
│  我可以帮你：                            │
│  ✨ 起草和编辑文档                        │
│  ✨ 修改语法和措辞                       │
│  ✨ 调整写作风格                         │
│                                         │
│  请注意：生成内容可能需要人工核实        │
└─────────────────────────────────────────┘
```

### 2. 处理不确定性

| 设计模式 | 适用场景 | 示例 |
|----------|----------|------|
| **置信度提示** | 答案可能不准确 | "我有 80% 的把握..." |
| **多选项展示** | 存在多种可能 | 展示 3 个候选答案 |
| **来源引用** | 事实性问题 | 引用来源链接 |
| **人机协作** | 高风险决策 | "建议人工审核" |

### 3. 渐进式披露

```
新手用户 → 简单界面，预设选项
    ↓
熟练用户 → 高级选项，自定义参数
    ↓
专家用户 → API 访问，批量处理
```

## 5.2.2 对话式设计

### 对话流程模板

```python
# examples/5-2-product/dialog_patterns.py
"""
常见对话设计模式
"""

DIALOG_PATTERNS = {
    "澄清式": {
        "trigger": "用户问题模糊",
        "response": "我不太确定您的意思，您是想问 A 还是 B？",
        "example": {
            "user": "怎么设置？",
            "bot": "请问您是想设置：\n1. 账号信息\n2. 通知偏好\n3. 隐私设置"
        }
    },
    
    "确认式": {
        "trigger": "执行重要操作",
        "response": "我理解您想要 [操作]，确认吗？",
        "example": {
            "user": "删除所有数据",
            "bot": "我理解您想要删除所有数据，这个操作无法撤销，确认继续吗？"
        }
    },
    
    "引导式": {
        "trigger": "用户不知道能做什么",
        "response": "我可以帮你...[列出选项]",
        "example": {
            "user": "你好",
            "bot": "你好！我可以帮你：\n- 回答问题\n- 创作文档\n- 分析数据\n请问需要什么帮助？"
        }
    },
    
    "修复式": {
        "trigger": "AI 理解错误",
        "response": "抱歉我理解错了，您是想要...吗？",
        "example": {
            "user": "不是这个，我要昨天的",
            "bot": "抱歉我理解错了，您是要查看昨天的数据对吗？"
        }
    }
}
```

### 错误状态设计

```
AI 产品常见错误状态及处理：

┌──────────────────┬───────────────────────┬─────────────────────┐
│ 错误类型          │ 用户感知              │ 推荐处理            │
├──────────────────┼───────────────────────┼─────────────────────┤
│ API 超时          │ "正在思考..."         │ 重试 + 进度提示      │
│ 内容被过滤        │ "无法回答"            │ 解释原因 + 引导改写  │
│ 模型不确定        │ "可能是..."           │ 表达不确定性        │
│ 上下文过长        │ "记忆有限"            │ 提示总结或新对话    │
│ 服务不可用        │ "暂时无法使用"        │ 离线功能 + 稍后重试 │
└──────────────────┴───────────────────────┴─────────────────────┘
```

## 5.2.3 评估用户体验

### AI 产品 UX 指标

| 指标 | 定义 | 目标值 |
|------|------|--------|
| **任务完成率** | 用户成功完成任务的比例 | >80% |
| **重试率** | 用户重新提问的比例 | <20% |
| **满意度评分** | 用户主观评分 (1-5) | >4.0 |
| **会话长度** | 平均交互轮次 | 3-8 轮 |
| **升级率** | 转人工客服的比例 | <10% |

### 用户测试方法

```markdown
## AI 产品可用性测试脚本

### 任务 1：核心功能测试
**场景**: 用户想要 [完成某个任务]
**观察点**:
- 用户能否理解系统能力？
- 用户如何表达自己的需求？
- 遇到困难时如何反应？

### 任务 2：错误恢复测试
**场景**: 故意触发一个错误（如模糊输入）
**观察点**:
- 用户是否理解错误提示？
- 用户能否成功纠正？

### 任务 3：边界情况测试
**场景**: 提出系统无法回答的问题
**观察点**:
- 用户如何理解拒绝回答？
- 引导是否有效？
```

- **用户输入**: 文本/语音/图片

- 输入区域设计
- 响应展示方式
- 加载状态设计

- 恢复引导机制

### 4.2 体验指标

## 5. 风险与合规

## 5.2.5 大模型原生交互模式（LLM-Native UX）

对话式设计之外，生产级大模型产品有一套特有的交互范式，直接决定用户信任与效率。

### 1. 流式输出与"思考可见"

- **逐字流式（SSE）** 是刚需：首字延迟（TTFT）比总时长更影响感知；配合"正在思考/正在检索"的状态骨架，避免用户面对空白等待。
- 推理模型时代，可展示**思考进度**（"正在分析第 3 个方案…"）但折叠详细推理链，兼顾透明与噪音。

### 2. 引用与溯源（Citation）

- RAG 回答必须带来源卡片（文档名、页码、链接），可点击核验。这是建立信任、满足合规、降低幻觉纠纷的关键设计。
- 事实性陈述"有据可依"、无据时明确表达不确定（"我没有找到相关资料"），而不是强行回答。

### 3. 可操作的输出（Generative UI / Action）

- 输出不只是文本：结构化结果直接渲染为**卡片、表格、图表、可编辑表单、待办、按钮**（生成式 UI）。
- 每个 AI 建议旁边放"采纳/修改/重新生成/复制"操作，让用户低成本纠偏。

### 4. 人机协作控制面（HITL UI）

Agent 产品的核心交互是"**自动驾驶 + 可接管**"：

| 场景 | UI 模式 |
|------|---------|
| 低风险动作（搜索、汇总） | 自动执行，过程可见 |
| 中风险（发草稿、改非关键字段） | 先预览，一键确认 |
| 高风险（发送、删除、支付、生产变更） | 审批卡片：动作+参数+影响面+理由，批准/拒绝/改参数 |
| AI 不确定/卡住 | 主动求助，提供选项让用户补全（对应 MCP Elicitation） |

### 5. 反馈闭环产品化

- 每条回答旁的 👍/👎、"重新生成"、"标记问题"要**轻量到一键**；点踩后可选项化原因（事实错/过时/语气/无用）。
- 反馈数据进入 badcase 队列 → 评测集/数据飞轮（见 3.6），形成"越用越好"的产品叙事。

### 6. 不确定性与失败的诚实设计

- 明确能力边界与失败兜底（转人工、给人工渠道）；
- 关键场景（医疗/法律/金融）加免责声明 + 人工复核入口；
- 宁可"说不知道"，不可"自信地错"。

```
大模型产品信任公式：
信任 = 能力（任务成功率）× 透明（引用/过程可见）× 可控（可纠错/可接管/有兜底）
```

## 练习题

1. **期望管理**：为一个医疗问答 AI 设计能力边界说明。

2. **错误恢复**：设计一个对话流程，处理用户连续 3 次不满意的情况。

3. **用户体验测试**：设计 5 个测试任务，评估 AI 写作助手的可用性。
4. **引用设计**：为企业知识库问答设计来源引用 UI，说明点击引用后用户看到什么、无来源时如何表现。
5. **审批卡片**：为"Agent 自动提交报销单"设计高风险动作的审批卡片，列出必须包含的 5 个信息要素。
6. **信任公式**：用 5.2.5 的信任公式分析一个你常用 AI 产品在能力/透明/可控上的短板，并给出改进。
