# 5.6 行业大模型具体应用

> 通用大模型提供"听说读写"的基础能力，行业 Know-how（私有知识、业务流程、合规要求）决定它能不能在一个行业真正上岗。本节按行业拆解大模型的具体落地场景、技术方案与坑点。

## 学习目标

学完本节后，你将能够：

- [ ] 说出大模型行业落地的四类共性模式
- [ ] 为金融、医疗、法律、制造、零售、教育、政务、客服等行业列举典型场景
- [ ] 针对一个行业场景，判断该用 RAG / Agent / 微调哪种技术路线
- [ ] 说清各行业的数据要求、效果指标与合规红线
- [ ] 在 API 调用、开源部署、自建行业模型之间做选型

---

## 5.6.1 行业落地的四类共性模式

抛开行业差异，大模型在各行各业的应用可归纳为四种技术形态（可组合）：

| 模式 | 解决什么 | 典型技术 | 适用判断 |
|------|----------|----------|----------|
| **知识问答 / 文档处理** | 企业知识散在文档里，查不到、读不完 | RAG、文档解析、向量检索 | 答案能从现有文档中找到 |
| **内容生成** | 重复性文案/代码/报告撰写 | 提示工程、模板、工作流 | 输出是文本/代码，有人审核 |
| **流程自动化（Agent）** | 跨系统的多步操作、人工流程 | Function Calling、工具调用、工作流 | 步骤可拆解、有明确工具 API |
| **辅助决策 / 分析洞察** | 从数据中总结、归因、给建议 | 大模型 + 数据分析（Text2SQL/BI） | 需要结合结构化数据与推理 |

**技术路线选择**（大多数行业场景的决策顺序）：

```
1. 先用提示工程 + 通用大模型 API 验证 → 80% 的内容生成场景到此为止
2. 答案需要企业私有知识 → 加 RAG（不要急着微调）
3. 需要操作业务系统、多步流程 → 加 Agent / 工作流编排
4. 有领域术语、固定风格、强合规且 RAG 解决不了 → 才考虑微调
5. 数据敏感、不能出域 → 开源自建 / 私有化部署
```

> 经验法则：**RAG 解决"知道什么"，微调改变"怎么说/怎么想"，Agent 解决"怎么做"**。行业落地 70% 是 RAG + 工作流，微调是少数。

## 5.6.2 金融行业

**特点**：数据密集、容错低、合规最严、预算充足。

| 场景 | 技术方案 | 效果指标 | 合规红线 |
|------|----------|----------|----------|
| 智能投研/研报分析 | RAG 接研报/公告/财报 + 长文档摘要 | 信息命中率、引用可溯源 | 不得提供具体荐股承诺 |
| 智能客服（查询/理财咨询） | RAG + Agent（查账户/产品） | 解决率、转人工率 | 不得承诺收益、适当性管理 |
| 信贷/风控报告辅助 | 大模型 + 结构化数据归因 | 审核提效、一致性 | 授信决策必须人工拍板 |
| 合同/合规文档审查 | RAG + 条款抽取 + 风险标注 | 风险召回率、漏审率 | 数据不出域、留痕审计 |
| 反洗钱/欺诈研判 | Agent 汇总多源信息生成研判报告 | 研判提效、覆盖度 | 模型可解释、可追溯 |
| 代码/报表开发 | 代码生成 + Text2SQL | 开发提效 | 生产数据脱敏 |

落地要点：金融强监管，**私有部署 + 数据不出域**是主流；所有结论必须给出来源、AI 仅做辅助、关键决策人工确认；幻觉容忍度极低，RAG 的引用溯源是硬要求。

## 5.6.3 医疗健康

**特点**：专业门槛最高、人命关天、隐私极强（病历属敏感个人信息）。

| 场景 | 技术方案 | 效果指标 | 合规红线 |
|------|----------|----------|----------|
| 医学知识问答/患教 | RAG 接指南/说明书 | 回答准确性、引用率 | 不得替代诊断，需免责声明 |
| 电子病历结构化/摘要 | 文档解析 + 信息抽取 | 抽取准确率、医生采纳率 | 病历数据脱敏、院内部署 |
| 辅助诊断/鉴别诊断 | 大模型 + 医学知识库 + 推理 | 与医生一致率、灵敏度 | 仅辅助，医生最终负责 |
| 医学文献综述 | RAG + 长文综合 | 证据覆盖度、可溯源 | 循证、标注证据等级 |
| 医保/病案编码 | Text2Code、规则+模型 | 编码准确率 | 规则兜底 |
| 药物研发/知识图谱 | LLM + 知识图谱 | 检索提效 | 实验验证为准 |

落地要点：医疗是**辅助而非替代**，定位是医生的"第二意见"和文书减负工具；必须院内私有化部署、数据脱敏；高风险结论给循证来源；产品通常按医疗器械软件（SaMD）监管，需关注注册审批。

## 5.6.4 法律行业

**特点**：依赖海量条文/判例、表述要求精确、责任明确。

| 场景 | 技术方案 | 效果指标 | 合规红线 |
|------|----------|----------|----------|
| 合同审查 | RAG 接合同模板/法规 + 条款风险点抽取 | 风险点召回、漏审率 | 律师审核定稿 |
| 法律问答/咨询 | RAG 接法规库/判例库 | 答案准确率、引用法条 | 不构成法律意见 |
| 文书起草（起诉状/答辩状） | 模板 + 生成 | 起草提效、采纳率 | 律师负责 |
| 案例检索/类案推送 | 语义检索 + RAG | 检索召回率 | 判例时效性 |
| 尽调报告 | Agent 汇总多文档 | 覆盖度、提效 | 数据保密 |

落地要点：法律行业**幻觉是致命的**（编造法条/判例），必须强 RAG 且每条结论附可核验的法条/案号；定位律师助理，最终由执业律师签字负责；律所/法务数据保密要求高。

## 5.6.5 制造业

**特点**：场景分散、现场数据多（设备日志、工艺参数）、强调降本增效。

| 场景 | 技术方案 | 效果指标 |
|------|----------|----------|
| 设备故障诊断/维修助手 | RAG 接维修手册 + 日志分析 | 故障定位时间、一次修复率 |
| 工艺知识问答 | RAG 接工艺规程/SOP | 查询提效 |
| 工业质检（视觉） | 多模态大模型/视觉模型 | 漏检率、过杀率 |
| 生产报表/异常归因 | Text2SQL + 数据洞察 | 报表自动化率 |
| 供应链/采购辅助 | Agent 汇总订单库存 | 响应时间 |
| 研发文档/图纸辅助 | 文档理解 + 多模态 | 知识复用 |

落地要点：制造业价值在**现场知识沉淀**——把老师傅经验、维修手册、SOP 变成可检索知识；常需对接 MES/ERP/SCADA 系统；多模态（看仪表、看缺陷）需求上升；模型要能边缘/内网部署。

## 5.6.6 零售与电商

**特点**：面向消费者、数据量大、追求转化率、迭代快。

| 场景 | 技术方案 | 效果指标 |
|------|----------|----------|
| 智能导购/客服 | Agent + RAG（商品库）+ 推荐 | 转化率、解决率、客单 |
| 商品文案/详情生成 | 生成 + 模板 | 内容产出效率 |
| 商品理解/多模态打标 | 多模态识别图文 | 打标准确率 |
| 评论分析/舆情 | 情感分析 + 聚类 | 洞察时效 |
| 营销话术/私域运营 | 生成 + Agent | 打开率、转化 |
| 虚拟试穿/搭配 | 多模态生成 | 互动率 |

落地要点：零售**直接挂钩 GMV**，ROI 最好算；客服+导购是最高频入口；多模态商品理解和个性化推荐是差异点；需对接商品库、订单、会员系统。

## 5.6.7 教育

**特点**：强调因材施教、内容准确性、面向未成年人有特殊要求。

| 场景 | 技术方案 | 效果指标 |
|------|----------|----------|
| AI 答疑/讲题 | RAG 教材 + 分步推理（CoT） | 讲解正确率、追问答疑 |
| 个性化学习路径 | Agent + 学习画像 | 完课率、提分 |
| 作文/口语批改 | 生成 + 评价模型 | 批改一致性 |
| 备课/出题助手 | 生成 + RAG 课标 | 教师提效 |
| 内容生成（题库/课件） | 生成 | 产出效率 |

落地要点：教育要**防错误知识误导学生**，内容准确性要求高；面向未成年人需内容安全过滤；产品要"AI + 老师"配合；CoT 分步讲解比直接给答案更有教学价值。

## 5.6.8 政务与公共服务

**特点**：政策文件多、办事流程复杂、强调权威性和安全可控。

| 场景 | 技术方案 | 效果指标 | 合规红线 |
|------|----------|----------|----------|
| 政策问答/办事指南 | RAG 接政策库 | 准确率、引用政策原文 | 答案权威、溯源 |
| 公文写作辅助 | 模板 + 生成 | 起草提效 | 保密、内网部署 |
| 12345 工单分类/派单 | 分类 + Agent | 派单准确率、响应时间 | 数据安全 |
| 政务热线智能客服 | RAG + Agent | 解决率 | 不留隐私、可审计 |

落地要点：政务**信创/国产化、私有化、等保合规**是硬门槛；回答必须引用权威政策原文；涉密内网与互联网物理隔离，通常用国产大模型私有部署。

## 5.6.9 其他高频行业速览

| 行业 | 高频场景 | 一句话要点 |
|------|----------|-----------|
| **客服/联络中心（跨行业）** | 智能问答、工单摘要、坐席辅助、质检 | 落地最成熟，衡量转人工率与一次解决率 |
| **人力资源** | 简历筛选、JD 生成、面试纪要、政策问答 | 注意招聘歧视与隐私 |
| **房地产** | 房源文案、带看问答、合同辅助 | 多模态 + 知识库 |
| **物流/供应链** | 运单处理、调度辅助、异常预警 | 对接 TMS/WMS |
| **能源/电力** | 巡检报告、规程问答、故障研判 | 安全生产，内网部署 |
| **传媒/营销** | 文案、视频脚本、多模态素材生成 | 版权与事实核查 |
| **软件/IT（开发者工具）** | 代码生成、单测、代码审查、文档 | Copilot 类，ROI 明确 |
| **科研** | 文献综述、实验数据分析、论文润色 | 可溯源、防造假 |

## 5.6.10 行业选型：API、开源还是自建？

| 路线 | 成本 | 数据安全 | 可控性 | 适用 |
|------|------|----------|--------|------|
| **调用商业 API**（闭源） | 按量付费、起步低 | 数据出域 | 低 | 中小团队、非敏感、快速验证 |
| **开源自建/私有化**（Llama/Qwen/DeepSeek 等） | 算力 + 运维成本 | 数据不出域 | 高 | 金融/医疗/政务、强合规 |
| **行业专属模型**（在开源上微调） | 数据 + 训练成本最高 | 可控 | 最高 | 有独特数据、规模大、护城河深 |

决策建议：

- **绝大多数企业**：从商业 API + RAG 起步验证价值，再根据数据合规和成本决定是否私有化
- **强监管行业**：直接走开源模型私有化部署（国产模型 + 信创）
- **微调的触发条件**：有大量高质量领域数据、RAG 无法解决术语/风格/推理问题、调用量足够大到摊薄训练成本
- **不要为了"自研大模型"而自研**：基础模型是军备竞赛，企业的护城河在私有数据和业务流程，不在模型参数

## 5.6.11 行业落地通用成败清单

**成功要素**：
- 从高频、高价值、容错相对高的场景切入（客服、文档、辅助类先行）
- 私有知识/数据打通是关键，RAG 知识库质量直接决定效果
- 人机协同定位清晰：AI 起草/建议，人审核/拍板
- 业务专家深度参与，评测集来自真实业务
- 合规与安全前置设计，不是上线前补

**失败模式**：
- 一上来追求"全自动替代人"，忽视流程与责任边界
- 知识库不治理（陈旧、无权限、全量灌入），答案不可信
- 用通用能力做高精度决策（算账、授信、诊断），幻觉出事
- 没有评测集和线上指标，"感觉还行"就上线
- 让用户切换到独立 AI 工具，不嵌入业务流程，无人使用

### 基础题

1. 归纳行业落地的四类共性模式，并各举一个你所在/熟悉行业的例子。

2. 为什么说"行业落地 70% 是 RAG + 工作流，微调是少数"？什么情况下才应该微调？

3. 对比金融、医疗、零售三个行业，在容错率、数据合规、AI 定位（替代 vs 辅助）上的差异。

### 实践题
