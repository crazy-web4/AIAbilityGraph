## 1. 数学与统计基础

| 术语 | 释义 |
|------|------|
| ⭐ **标量 / 向量 / 矩阵 / 张量（Scalar/Vector/Matrix/Tensor）** | 0/1/2/N 维数组。神经网络中所有数据（输入、权重、激活）都表示为张量；GPU 并行计算的基本对象。 |
| ⭐ **线性变换（Linear Transformation）** | `y = Wx + b`，全连接层的本质。权重矩阵 W 把输入空间旋转/缩放/平移到输出空间。 |
| **点积 / 内积（Dot Product）** | 两向量对应元素乘积之和，衡量"方向相似度"。注意力分数、embedding 相似度都靠它。 |
| ⭐ **特征值与特征向量（Eigenvalue/Eigenvector）** | 矩阵作用于某向量只伸缩不改变方向时，该向量为特征向量、伸缩倍数为特征值。PCA 的数学基础。 |
| 🔬 **奇异值分解（SVD）** | 把任意矩阵分解为 `UΣVᵀ`，低秩近似、PCA、推荐系统、LoRA 的低秩思想都源于此。 |
| **范数（Norm）** | 向量"长度"的度量。L1 范数（绝对值和）促进稀疏、L2 范数（平方和开根）对应欧氏距离；L2 正则即权重衰减。 |
| ⭐ **导数 / 偏导数 / 梯度（Derivative/Gradient）** | 函数变化率；多元函数对各变量的偏导组成梯度向量，指向函数上升最快方向；梯度下降沿反方向更新参数。 |
| ⭐ **链式法则（Chain Rule）** | 复合函数求导法则 `dy/dx = dy/du · du/dx`；反向传播（BP）就是链式法则在计算图上的逐层应用。 |
| **雅可比矩阵 / 海森矩阵（Jacobian/Hessian）** | 一阶/二阶偏导构成的矩阵；海森矩阵描述曲率，二阶优化法（牛顿法）用到，深度学习一般不用（太贵）。 |
| ⭐ **凸函数 / 非凸优化（Convex/Non-convex）** | 凸函数只有一个全局最优；神经网络损失面高度非凸，梯度下降只保证收敛到局部最优，靠初始化/噪声/规模绕过。 |
| ⭐ **概率 / 条件概率 / 联合概率** | P(A)、P(A\|B)（B 发生下 A 的概率）、P(A,B)（同时发生）。贝叶斯定理连接三者。 |
| ⭐ **贝叶斯定理（Bayes' Theorem）** | `P(A\|B) = P(B\|A)P(A)/P(B)`，用新证据更新先验 belief。朴素贝叶斯分类器、贝叶斯优化的基础。 |
| **随机变量 / 概率分布** | 随机取值的变量及其取值概率规律。离散（伯努利、分类、泊松）与连续（均匀、正态、指数）。 |
| ⭐ **正态分布（高斯分布）** | 钟形分布，由均值 μ、方差 σ² 决定；中心极限定理解释其普遍性；权重初始化、噪声注入常假设高斯。 |
| **期望 / 方差 / 标准差** | 分布的均值（期望）、离散程度（方差）、与原量纲一致的离散度（标准差）。 |
| ⭐ **最大似然估计（MLE）** | 选择使"观测数据出现概率"最大的参数；交叉熵损失就是分类问题 MLE 的等价形式。 |
| **最大后验估计（MAP）** | MLE + 先验，等价于"带正则项的 MLE"；L2 正则 ↔ 高斯先验，L1 正则 ↔ 拉普拉斯先验。 |
| ⭐ **信息熵（Entropy）** | 随机变量不确定性的度量，`H = -Σp log p`；分布越均匀熵越高。决策树分裂、好奇心奖励用到。 |
| ⭐ **交叉熵（Cross-Entropy）** | 衡量两个分布差异，`-Σp log q`；分类任务的标准损失函数，也是大模型 next-token 预测的损失。 |
| **KL 散度 / JS 散度** | 衡量两分布差异的非对称度量（KL）与其对称平滑版（JS）；知识蒸馏、RLHF 奖励模型的理论基础。 |
| ⭐ **采样（Sampling）** | 从概率分布抽取具体值。LLM 解码时从词表概率分布采样下一个 token。 |
| **蒙特卡洛方法** | 用大量随机采样近似求解（期望、积分）；LLM 多次采样投票（self-consistency）是其思想应用。 |
| **假设检验 / p 值** | 判断观测差异是否"统计显著"；A/B 实验比较模型版本效果的标准工具。 |
| ⭐ **置信区间** | 以一定概率（如 95%）包含真值的区间；评测分数必须带置信区间，否则 1% 的提升可能只是噪声。 |
| **偏差-方差权衡（Bias-Variance Tradeoff）** | 模型误差 = 偏差（欠拟合）+ 方差（过拟合）+ 不可约噪声；正则化、集成、数据量都在调节这对矛盾。 |
| **大数定律 / 中心极限定理** | 样本越多样本均值越接近期望；独立随机因素之和趋近正态分布——统计推断的两大支柱。 |
| **余弦相似度（Cosine Similarity）** | 两向量夹角余弦，只看方向不看长度；embedding 检索、RAG 语义匹配的默认相似度。 |

## 2. 经典机器学习

| 术语 | 释义 |
|------|------|
| ⭐ **监督学习（Supervised Learning）** | 用带标签数据 `(x, y)` 学习输入到输出的映射；分类与回归是两大任务。 |
| ⭐ **无监督学习（Unsupervised Learning）** | 从无标签数据中发现结构：聚类（K-Means）、降维（PCA）、密度估计。 |
| **自监督学习（Self-Supervised Learning, SSL）** | 从数据自身构造标签（如掩码预测、下一句预测）；预训练大模型的核心范式，BERT/GPT 都属此类。 |
| **半监督 / 弱监督学习** | 少量标签 + 大量无标签；用启发式规则/远程标注产生"弱标签"。 |
| ⭐ **强化学习（Reinforcement Learning, RL）** | 智能体在环境中试错，靠奖励信号学习策略；RLHF/RLAIF/GRPO 把 RL 用于对齐大模型。 |
| ⭐ **分类 / 回归** | 预测离散类别 / 连续数值。逻辑回归虽名"回归"实为分类。 |
| **训练集 / 验证集 / 测试集** | 拟合参数 / 调超参选模型 / 最终评估；三者泄漏（data leakage）是最常见的实验错误。 |
| ⭐ **过拟合 / 欠拟合** | 模型记住训练集噪声导致泛化差 / 连训练集都没学好；表现为训练误差低验证误差高 / 两者都高。 |
| ⭐ **正则化（Regularization）** | 抑制过拟合的手段：L1/L2 权重惩罚、Dropout、数据增强、早停、标签平滑。 |
| **线性回归 / 逻辑回归** | 回归基线 / 用 sigmoid 把线性输出压到概率的分类基线；面试常考逻辑回归为什么用对数损失。 |
| **决策树 / 随机森林** | 递归划分特征空间的可解释模型；多棵树投票/平均的集成模型，表格数据强基线。 |
| **梯度提升树（GBDT/XGBoost/LightGBM）** | 串行训练弱树拟合残差；结构化表格数据上长期是王者，风控/推荐排序常用。 |
| ⭐ **支持向量机（SVM）** | 在特征空间找最大间隔分类超平面，核技巧处理非线性；深度学习前的主流分类器。 |
| **K 近邻（KNN）** | "近朱者赤"：按最近的 K 个邻居投票；无需训练但推理慢，RAG 向量检索本质是 KNN。 |
| **K-Means 聚类** | 迭代分配簇中心的无监督算法；用户分群、embedding 去重、RAG 聚类摘要都能用。 |
| ⭐ **主成分分析（PCA）** | 线性降维，找方差最大的正交方向；可视化高维 embedding、去噪、压缩。 |
| **朴素贝叶斯（Naive Bayes）** | 基于贝叶斯定理 + 特征条件独立假设；文本分类基线，快但假设过强。 |
| ⭐ **集成学习（Ensemble）** | Bagging（并行，随机森林，降方差）与 Boosting（串行，GBDT，降偏差）；LLM 多次采样/多模型投票是同源思想。 |
| ⭐ **特征工程（Feature Engineering）** | 把原始数据变成模型可用特征；深度学习把这步自动化了，但 RAG/传统 ML 中仍决定上限。 |
| **标准化 / 归一化（Normalization）** | 把特征缩放到均值 0 方差 1（z-score）或 [0,1]；距离类模型和梯度下降都受益。 |
| **精确率 / 召回率 / F1（Precision/Recall/F1）** | `P=TP/(TP+FP)`、`R=TP/(TP+FN)`、F1 为调和平均；RAG 检索评估、内容安全过滤的核心指标。 |
| ⭐ **准确率的陷阱** | 类别不平衡时准确率虚高（99% 负样本全猜负就有 99%）；要看混淆矩阵/PR 曲线/ROC-AUC。 |
| **ROC-AUC** | 不同阈值下 TPR-FPR 曲线下面积，衡量排序能力；不平衡数据配合 PR-AUC 看。 |
| **交叉验证（Cross-Validation）** | K 折轮换验证集，更稳地评估小数据集；大模型时代少用但仍是基本功。 |
| **超参数（Hyperparameter）** | 训练前设定、不学自数据的参数（学习率、batch size、层数）；区别于可学习参数权重。 |
| ⭐ **梯度下降（GD/SGD/mini-batch）** | 沿梯度反方向更新参数；全量 GD 慢、单样本 SGD 噪声大、mini-batch 是主流折中。 |
| **学习率（Learning Rate, LR）** | 每步更新步长；最重要的超参数，太大发散太小收敛慢，常用 warmup + cosine 衰减调度。 |

## 3. 深度学习基础

| 术语 | 释义 |
|------|------|
| ⭐ **神经网络（Neural Network）** | 由神经元（线性变换 + 非线性激活）层层堆叠的可微函数；万能近似定理保证足够宽的网络能拟合任意连续函数。 |
| ⭐ **激活函数（Activation Function）** | 引入非线性：ReLU（最常用，`max(0,x)`）、GELU/SiGLU（Transformer 主流）、sigmoid（门控/概率）、tanh。无激活函数多层网络等价单层。 |
| ⭐ **前向传播 / 反向传播（Forward/Backpropagation）** | 前向算预测与损失；反向用链式法则算每个参数的梯度；再由优化器更新参数。 |
| ⭐ **损失函数（Loss Function）** | 衡量预测与真值差距：回归 MSE、分类交叉熵、对比学习 InfoNCE、大模型 next-token 交叉熵。 |
| ⭐ **优化器（Optimizer）** | 用梯度更新参数的算法：SGD+momentum、Adam（自适应学习率，最常用）、AdamW（解耦权重衰减，Transformer 标配）。 |
| **Epoch / Batch / Iteration** | 遍历全量数据一次 / 一次并行喂入的样本数（batch size）/ 一次参数更新；大模型训练常只跑 1–2 个 epoch。 |
| ⭐ **学习率调度（LR Scheduling）** | warmup（线性爬升防初期发散）+ cosine/线性衰减；大模型预训练标配。 |
| ⭐ **感知机 / MLP（多层感知机）** | 最基础的全连接前馈网络；Transformer 中的 FFN 就是两层 MLP。 |
| ⭐ **CNN（卷积神经网络）** | 用卷积核提取局部平移不变特征，参数共享；图像领域基础（ResNet/VGG），多模态视觉编码器常用 ViT。 |
| **卷积 / 池化（Convolution/Pooling）** | 局部加权滑动求和 / 降采样（最大/平均）；前者提特征后者降尺寸增不变性。 |
| ⭐ **RNN / LSTM / GRU** | 按时间步递归处理序列的网络，隐状态传递历史；长序列梯度消失，LSTM 用门控缓解，已基本被 Transformer 取代。 |
| 🔬 **梯度消失 / 梯度爆炸** | 深层连乘使梯度过小（学不动）或过大（发散）；对策：残差连接、LayerNorm、合理初始化、梯度裁剪。 |
| ⭐ **残差连接（Residual Connection）** | `output = x + F(x)`，让梯度有"高速公路"直达浅层；ResNet 与 Transformer 的关键结构。 |
| ⭐ **层归一化（LayerNorm）** | 对单个样本的特征维做归一化，稳定深层训练；Transformer 用 Pre-LN（现代）或 Post-LN。 |
| **批归一化（BatchNorm）** | 对 batch 维归一化，CNN 常用；依赖 batch 统计量，NLP/大模型多用 LayerNorm/RMSNorm。 |
| ⭐ **Dropout** | 训练时随机置零部分神经元，强制冗余、防过拟合；大模型预训练常用小比例 dropout 或不用。 |
| ⭐ **注意力机制（Attention）** | 按 query-key 相似度对 value 加权求和，实现序列内"软查找"；Transformer 的核心。 |
| ⭐ **自注意力（Self-Attention）** | Q/K/V 都来自同一序列，建模 token 间两两关系；复杂度 O(n²)，是长上下文的主要开销。 |
| 🔬 **缩放点积注意力** | `Attention(Q,K,V)=softmax(QKᵀ/√d)V`；除以 √d 防止点积过大使 softmax 饱和。 |
| ⭐ **多头注意力（Multi-Head Attention）** | 把 Q/K/V 拆成多组并行注意力再拼接，让模型同时关注不同子空间的关系。 |
| ⭐ **Transformer** | 2017 年《Attention Is All You Need》提出，仅用注意力 + FFN + 残差 + LayerNorm 的编码器-解码器架构；现代大模型的统一骨架。 |
| **编码器 / 解码器（Encoder/Decoder）** | Encoder 双向理解（BERT 系，适合分类/检索）；Decoder 自回归生成（GPT 系，适合生成）；T5 为 encoder-decoder。 |
| ⭐ **位置编码（Positional Encoding）** | 注意力本身无序，需注入位置信息：绝对正弦编码、可学习位置、RoPE（旋转位置编码，LLaMA/Qwen 主流，支持外推）、ALiBi。 |
| 🔬 **RoPE（旋转位置编码）** | 对 Q/K 做与位置相关的旋转，把相对位置编码进点积；外推性好，是长上下文扩展的基础。 |
| ⭐ **词表 / 分词（Tokenization）** | BPE（字节对编码）/ SentencePiece / tiktoken，把文本切成 subword token；token 是计费与上下文长度的单位。 |
| **Embedding（词嵌入）** | 把离散 token 映射为稠密向量；语义相近的词向量相近；输入 embedding 与输出 lm_head 常共享权重。 |
| ⭐ **Softmax** | 把 logits 归一化为概率分布（指数归一化）；温度越高分布越平（越随机）。 |
| **温度（Temperature）/ Top-k / Top-p** | 解码采样参数：温度控随机性、Top-k 只在 k 个最高概率 token 中采、Top-p（nucleus）在累计概率 p 的最小集合中采。 |
| ⭐ **贪心 / 束搜索（Greedy/Beam Search）** | 每步取概率最高 / 保留 k 条最优路径；确定性任务用，创造性任务用采样。 |
| **前馈网络（FFN/MLP 层）** | Transformer 每层注意力后的两层全连接（常带 SwiGLU），负责知识存储与变换；参数量主要集中在 FFN。 |
| ⭐ **MoE（混合专家，Mixture of Experts）** | FFN 换成多个"专家"子网络 + 路由器，每 token 只激活少数专家；以小计算量换大参数量（DeepSeek-MoE/Mixtral/Qwen-MoE）。 |
| 🔬 **门控网络 / 路由器（Gating/Router）** | MoE 中决定 token 发给哪个专家的小网络；负载均衡损失防止专家忙闲不均。 |
| **计算量 FLOPs / 参数量 Params** | FLOPs 衡量算力开销（推理延迟相关），参数量衡量模型容量（显存相关）；MoE 参数量大但单 token FLOPs 小。 |
| ⭐ **迁移学习（Transfer Learning）** | 把预训练知识迁移到下游任务；微调、prompt、few-shot 都是迁移学习的形式。 |
| **课程学习 / 数据配比** | 由易到难安排训练数据；预训练数据来源/质量的混合比例显著影响模型能力。 |

## 4. 大模型架构

| 术语 | 释义 |
|------|------|
| ⭐ **大语言模型（LLM）** | 以 Transformer 解码器为骨架、在海量文本上自监督预训练、规模达数十亿至数千亿参数的语言模型；核心能力是 next-token 预测。 |
| ⭐ **基础模型（Foundation Model）** | 经大规模预训练、可通过微调/提示适配众多下游任务的模型（LLM、视觉、多模态的统称）。 |
| ⭐ **预训练（Pre-training）** | 在万亿 token 上做 next-token 预测，习得语言、知识、推理能力；成本数百万至数亿元，决定模型底座。 |
| ⭐ **后训练（Post-training）** | 预训练后的一切：SFT、RLHF/DPO、蒸馏、安全对齐；决定模型"好不好用、听不听话"。 |
| ⭐ **Scaling Law（规模定律）** | 模型性能随参数量、数据量、算力呈幂律提升；Kaplan 2020 / Chinchilla（数据参数比 ~20 token/参数）。 |
| 🔬 **Chinchilla 定律** | DeepMind 提出：给定算力下模型参数与训练 token 应等比例放大；很多旧模型"训练不足"（参数过大 token 不够）。 |
| 🆕 **推理模型 / 测试时计算（Reasoning Model / Test-time Compute）** | o1/R1 类：把算力从训练时挪到推理时，靠长思维链（CoT）和强化学习提升复杂推理；详见 Special-07。 |
| ⭐ **上下文窗口（Context Window）** | 模型一次能处理的最大 token 数（含输入输出）；从 2k 演进到 128k/1M；受注意力 O(n²) 与 KV cache 显存限制。 |
| ⭐ **KV Cache** | 自回归生成时缓存历史 token 的 K/V 张量避免重复计算；是推理显存与批处理的核心矛盾。 |
| 🔬 **Prefill / Decode 阶段** | Prefill：并行处理输入 prompt 算首 token（compute-bound）；Decode：逐 token 生成（memory-bound）；分离式部署据此优化。 |
| ⭐ **涌现能力（Emergent Ability）** | 模型规模超过阈值后突然出现的能力（few-shot、推理）；近年研究认为部分是度量假象，考试常考"规模带来质变"的叙事。 |
| **幻觉（Hallucination）** | 模型生成流畅但不真实/无依据的内容；分事实性幻觉（错）与忠实性幻觉（违背上下文）；RAG/引用/校验是主要对策。 |
| ⭐ **GPT 系列** | OpenAI 的解码器-only 自回归模型：GPT-3 确立规模范式，GPT-3.5/4 引爆 ChatGPT，o 系列转向推理。 |
| ⭐ **BERT** | Google 编码器-only 双向掩码语言模型；引领预训练-微调范式，现代生成式 LLM 少直接用但影响深远。 |
| **T5** | encoder-decoder，把所有任务统一为 "text-to-text"；FLAN 系列指令微调源头之一。 |
| ⭐ **LLaMA 系列** | Meta 开放权重模型，事实标准级开源底座；LLaMA 3 后许可证宽松，催生大量衍生模型。 |
| ⭐ **Qwen（通义千问）** | 阿里开源系列，稠密 + MoE、文本 + 多模态全覆盖；国产开源生态主力。 |
| **DeepSeek 系列** | 以 MoE 架构创新（细粒度专家、共享专家、MLA）和开源 R1 推理模型著称，训练成本叙事影响行业。 |
| 🔬 **MLA（多头潜在注意力）** | DeepSeek 提出：对 K/V 做低秩压缩缓存，大幅降低 KV cache 显存；长上下文与高并发推理关键技术。 |
| 🔬 **GQA / MQA（分组/多查询注意力）** | 多个查询头共享 K/V 头（GQA）或全部共享（MQA），减少 KV cache 体积；LLaMA-2/3、Qwen 普遍采用。 |
| ⭐ **SwiGLU 激活** | Swish 门控线性单元，替代 ReLU 的 FFN 激活，现代 LLM 标配。 |
| **RMSNorm** | LayerNorm 的简化版（去均值、只缩放），计算更快效果相当；LLaMA/Qwen 采用。 |
| ⭐ **Tokenizer 与 token 经济** | 中文 1 字 ≈ 1–2 token、英文 1 词 ≈ 1–1.5 token；不同模型 tokenizer 不同，直接影响上下文长度与计费。 |
| ⭐ **指令微调（SFT, Supervised Fine-Tuning）** | 用"指令-回答"样本继续训练，让基座模型学会听懂指令、按对话格式回答；Chat 模型的第一道工序。 |
| ⭐ **RLHF（人类反馈强化学习）** | SFT → 训练奖励模型（RM）拟合人类偏好 → 用 PPO 等 RL 算法优化策略；ChatGPT 对齐的经典三步。 |
| ⭐ **DPO（直接偏好优化）** | 跳过显式奖励模型，用成对偏好数据直接优化策略，简单稳定；后训练主流替代 PPO 的方案之一。 |
| 🆕 **RLAIF / RLOO / GRPO** | 用 AI 反馈替代人类（RLAIF）；REINFORCE 系列简化变体；GRPO（Group Relative Policy Optimization，DeepSeek）用组内相对优势，省掉价值网络，R1 核心算法。 |
| ⭐ **对齐（Alignment）** | 让模型行为符合人类意图与价值观：有用（helpful）、诚实（honest）、无害（harmless），即 3H。 |
| **System Prompt** | 对话中最高优先级的系统指令，设定角色、规则、工具；Agent 平台常在此注入环境上下文。 |
| ⭐ **Temperature 与确定性** | T=0（贪心）输出近似确定，适合分类/抽取；T=0.7–1 适合创作；评测与生产流水线常用低温度保稳定。 |
| **Function Calling / Tool Use** | 模型按约定 schema 输出工具名与参数，由外部执行后回灌结果；Agent 行动能力的基础。 |
| ⭐ **结构化输出（Structured Output）** | 强制模型输出符合 JSON Schema；靠 JSON mode、约束解码（grammar/ outlines）或 function calling 实现。 |
| 🔬 **约束解码（Constrained Decoding）** | 在 logits 层面屏蔽不符合语法/schema 的 token，保证 100% 合法输出（Outlines/Guidance/xgrammar）。 |
| **Embedding 模型** | 把文本映射为向量的编码器模型（BGE、text-embedding-3、GTE）；RAG 检索、聚类、去重的基础。 |
| **Reranker（重排序模型）** | Cross-encoder 对 query-doc 对精排，比向量检索准但慢；RAG 两阶段检索的第二阶段。 |

## 5. 训练、预训练与微调

| 术语 | 释义 |
|------|------|
| ⭐ **语料（Corpus）** | 预训练/微调文本集合：网页（Common Crawl）、书籍、代码、论文、对话；数据质量 > 数量是现代共识。 |
| ⭐ **数据清洗管线** | 去重（MinHash/SimHash）、去噪（语言识别、质量分类器）、去毒、PII 脱敏；预训练成败的一半在数据。 |
| **数据配比（Data Mixture）** | 各类来源 token 的比例（网页/代码/数学/学术）；显著影响能力结构，是各家秘方。 |
| ⭐ **Tokenization 训练** | 在语料上学习 BPE 合并规则；词表大小通常 32k–128k，多语言模型需扩词表。 |
| 🔬 **因果语言建模（CLM）** | Decoder 目标：根据前文预测下一个 token，注意力掩码为下三角（只能看左侧）。 |
| 🔬 **掩码语言建模（MLM）** | BERT 目标：随机遮盖 token 让模型还原，双向可见；适合理解类任务。 |
| ⭐ **预训练阶段** | 通常分：预训练（万亿 token）→ 继续预训练/领域适配（CPT）→ SFT → 对齐。 |
| ⭐ **继续预训练（Continued Pre-Training, CPT/DA）** | 用领域语料（医疗/法律/代码）在基座上继续大规模 CLM，注入领域知识；比 SFT 深、比从零训便宜。 |
| ⭐ **指令微调（Instruction Tuning）** | 用多样化"指令+回答"样本 SFT，激发遵循指令能力；FLAN 验证其跨任务泛化收益。 |
| ⭐ **对话微调** | 指令微调的多轮对话特化，用 ChatML/消息模板训练模型理解角色与对话历史。 |
| **多任务微调** | 混合多种任务样本一起训，防止单任务过拟合、提升泛化。 |
| ⭐ **灾难性遗忘（Catastrophic Forgetting）** | 微调新知识时旧能力退化；对策：数据回放（混入通用数据）、小学习率、PEFT、正则。 |
| ⭐ **微调数据构建** | 种子指令 + 自生成（Self-Instruct/Evol-Instruct）+ 人工标注 + 真实日志脱敏；质量与多样性优先于数量。 |
| **学习率 / Epoch 设置经验** | SFT 用小 LR（1e-5 ~ 2e-5 量级，PEFT 可 1e-4~2e-4）、1–3 epoch；过大易过拟合/遗忘。 |
| **打包（Packing）** | 把多条短样本拼到固定长度序列提升 GPU 利用率；注意 attention mask 隔离。 |
| 🔬 **混合精度训练（AMP）** | FP16/BF16 计算 + FP32 主权重；BF16 数值范围大更稳，现代训练默认 BF16。 |
| ⭐ **损失缩放（Loss Scaling）** | FP16 下放大损失防梯度下溢；BF16 不需要。 |
| ⭐ **梯度累积（Gradient Accumulation）** | 多个 micro-batch 累加梯度再更新，用小显存模拟大 batch size。 |
| ⭐ **梯度检查点（Gradient Checkpointing）** | 不存中间激活、反向时重算，用 ~20% 额外计算换显存大幅下降。 |
| **ZeRO（零冗余优化器）** | 微软 DeepSpeed 提出，把优化器状态/梯度/参数切分到各卡（Stage 1/2/3）；大模型训练标配。 |
| ⭐ **LoRA（低秩适配）** | 冻结原权重，在旁边训练低秩矩阵 `ΔW=BA`（秩 r 通常 8–64）；参数量降数百倍，可插拔合并。详见 2.3。 |
| ⭐ **QLoRA** | LoRA + 4bit 量化基座（NF4 + 双重量化 + 分页优化器）；单卡微调数十 B 模型成为可能。 |
| **Adapter / Prefix/P-Tuning v2 / Prompt Tuning** | 早期 PEFT 家族：插入小模块 / 训练虚拟前缀；LoRA 流行后多作为补充。 |
| ⭐ **奖励模型（Reward Model, RM）** | 在成对偏好数据（chosen/rejected）上训练的打分模型，把人类偏好变成可优化标量。 |
| ⭐ **PPO（近端策略优化）** | 经典 RL 算法，clip 限制策略更新幅度；RLHF 标准但工程复杂、不稳定。 |
| 🔬 **KL 惩罚** | RLHF 中约束策略不偏离参考模型太远，防止奖励作弊（reward hacking）与退化。 |
| ⭐ **DPO / IPO / KTO / SimPO** | 无奖励模型的偏好优化家族：DPO 直接对比对数概率；KTO 只需"好/坏"二元标签；SimPO 去掉参考模型更省。 |
| 🆕 **RLVR（可验证奖励的强化学习）** | 用规则可判对错的奖励（数学答案、单测通过、格式正确）做 RL，无需人类标注与奖励模型；R1/o 系列推理能力来源。 |
| 🆕 **GRPO** | DeepSeek 的组相对策略优化：对同一 prompt 采样一组输出，用组内平均奖励作基线算优势，省去价值网络；R1 训练算法。 |
| 🆕 **拒绝采样 / RFT（Rejection sampling Fine-Tuning）** | 对每题采样多条，只保留正确/高分答案做 SFT（又称 STaR、best-of-n 蒸馏）；推理模型训练常用。 |
| ⭐ **蒸馏（Distillation）** | 用大模型（教师）的输出/ logits 训练小模型（学生）；分黑盒蒸馏（模仿回答）与白盒蒸馏（学 logits/隐状态）。 |
| 🔬 **知识蒸馏损失** | 学生学硬标签（真实答案）+ 软标签（教师 logits 带温度，暗知识）。 |
| **数据飞轮（Data Flywheel）** | 线上 badcase → 标注/合成 → 进训练集 → 模型变好 → 更多使用 → 更多 badcase 的正循环。 |

## 6. 参数高效微调与对齐

| 术语 | 释义 |
|------|------|
| ⭐ **PEFT 为什么有效** | 微调本质是低维适配：任务引起的权重变化矩阵是低秩的，少量参数即可表达。 |
| ⭐ **秩 r 与 alpha** | LoRA 秩越高容量越大越易过拟合；`scaling = alpha/r` 控制适配器贡献；常用 r=8/16/32，alpha=16/32。 |
| **目标模块选择** | LoRA 通常挂在 q/k/v/o_proj 与 gate/up/down_proj；只训 attention 省但知识注入弱，全模块效果好。 |
| ⭐ **LoRA 合并** | 推理时 `W' = W + BA·scale` 可合并回原权重，零额外推理开销；也可不合并做热切换。 |
| ⭐ **QLoRA 4bit** | NF4 量化 + double quantization + paged optimizer；显存从"全参数量级"降到"单卡 24–48G 微调 7B–70B"。 |
| **全参微调 vs PEFT** | 全参效果上限高但需多卡、易遗忘；PEFT 便宜、可多任务插拔、适合企业定制；知识注入优先 CPT/全参。 |
| ⭐ **对齐税（Alignment Tax）** | 对齐后能力（尤其数学/代码）可能下降的代价；好的对齐方案要兼顾，评测时要回归通用能力。 |
| **宪法 AI（Constitutional AI）** | Anthropic 方法：用一套明文原则（宪法）让模型自我批评/修订，产生 RLAIF 数据，减少人工标注。 |
| ⭐ **红队测试（Red Teaming）** | 主动攻击模型找安全漏洞（越狱、歧视、泄密）；安全对齐的必要环节。 |
| **越狱（Jailbreak）** | 通过特殊提示绕过安全限制；防御靠训练 + 输入输出过滤 + 系统提示加固的纵深防御。 |
| **过度拒答（Over-refusal）** | 安全对齐过度导致正常问题也拒绝；与漏答都是安全-有用权衡的两端。 |

## 7. 分布式训练与并行

| 术语 | 释义 |
|------|------|
| ⭐ **数据并行（Data Parallel, DP）** | 每卡持有完整模型副本、分不同数据，梯度 AllReduce 同步；最简单，DDP/ZeRO 属此类。 |
| ⭐ **张量并行（Tensor Parallel, TP）** | 单层内权重矩阵按行列切到多卡，每层需通信；节点内 NVLink 高速互联才划算。 |
| ⭐ **流水线并行（Pipeline Parallel, PP）** | 不同层放不同卡，微批次流水填充 bubble；通信少但有气泡开销。 |
| ⭐ **序列并行 / 上下文并行（SP/CP）** | 把超长序列维度切分到多卡；长上下文训练的关键。 |
| ⭐ **3D 并行** | DP × TP × PP 组合；千卡训 70B+ 的标准配方（如 TP=8, PP=16, DP=N）。 |
| 🧭 **专家并行（Expert Parallel, EP）** | MoE 专有：不同专家放不同卡，all-to-all 通信路由 token；MoE 训练效率核心。 |
| ⭐ **AllReduce / All2All 通信** | DP 梯度同步用 AllReduce（环式/树式）；MoE token 路由用 All2All；通信常是瓶颈。 |
| **DeepSpeed** | 微软训练框架：ZeRO 分片、Offload（优化器/参数卸到 CPU/NVMe）、MoE 支持。 |
| ⭐ **Megatron-LM** | NVIDIA 大模型训练框架：张量/流水线并行实现标杆，常与 DeepSpeed 组合。 |
| **FSDP（Fully Sharded Data Parallel）** | PyTorch 原生全分片（≈ ZeRO-3）；生态标准化方向。 |
| ⭐ **Accelerate / Trainer** | HuggingFace 的训练封装，统一多卡/混合精度/梯度累积配置，企业微调最常用。 |
| ⭐ **通信开销 vs 计算** | TP 通信最频繁（每层）→ 放节点内；PP 通信少 → 跨节点；这是并行切分的拓扑原则。 |
| 🔬 **MFU（Model FLOPs Utilization）** | 实测 FLOPs / 峰值 FLOPs；衡量训练效率，A100/H100 集群好的实现 40%–55%。 |
| **故障恢复 / Checkpoint** | 千卡训练日均故障多次：高频异步 checkpoint 到共享存储 + 自动续训是刚需。 |
| **网络互联** | IB/RoCE（200/400Gb）+ NVLink/NVSwitch；跨机带宽决定大规模并行可行性。 |

## 8. 模型压缩、量化与推理优化

| 术语 | 释义 |
|------|------|
| ⭐ **量化（Quantization）** | 把权重/激活从 FP16 降到 INT8/INT4/FP8，减显存提吞吐；分权重量化（W8A16）与权重量化+激活量化（W8A8）。 |
| ⭐ **GPTQ / AWQ / GGUF** | GPTQ：训练后逐层权重量化；AWQ：保护显著权重通道；GGUF：llama.cpp 生态格式，CPU/边缘部署主流。 |
| ⭐ **SmoothQuant** | 把激活的量化难度平滑转移到权重，实现 W8A8；INT8 推理常用。 |
| 🆕 **FP8 量化** | H100+ 原生支持 FP8（E4M3/E5M2），训练和推理都可用，精度损失小，是新卡红利。 |
| ⭐ **量化感知 / 训练后量化（QAT/PTQ）** | PTQ 无需训练直接量化（便宜）；QAT 训练时模拟量化（精度好成本高）。 |
| **NF4** | QLoRA 的 4bit 正态分布数据类型，理论最优的 4bit 正态权重量化。 |
| ⭐ **剪枝（Pruning）** | 移除不重要权重/头/层：结构化（整块删，可加速）与非结构化（稀疏，难加速）；LLM 上收益有限。 |
| ⭐ **知识蒸馏** | 见第 5 节；小模型学大模型，是"压缩 + 能力迁移"双重手段。 |
| ⭐ **vLLM / PagedAttention** | 主流推理引擎；PagedAttention 像 OS 管内存一样分页管理 KV cache，碎片少、吞吐高数倍。 |
| **SGLang / TensorRT-LLM** | SGLang：RadixAttention 前缀复用、结构化输出强；TRT-LLM：NVIDIA 极致延迟优化。 |
| ⭐ **连续批处理（Continuous Batching）** | 不等整批结束，逐 token 级别出入批，大幅提升 GPU 利用率（vs 静态批处理）。 |
| ⭐ **KV Cache 显存** | 显存占用 ≈ 2×层数×K/V头数×头维×序列长×精度；长上下文 + 高并发时占大头，是定价核心。 |
| ⭐ **Prefix Caching** | 缓存公共前缀（system prompt/历史）的 KV，重复请求直接复用；Anthropic/OpenAI/DeepSeek 官方 + vLLM 都支持。 |
| ⭐ **投机解码（Speculative Decoding）** | 小模型快速起草多 token、大模型并行校验，无损提速 1.5–3×。 |
| 🆕 **Medusa / EAGLE** | 投机解码变体：在主模型加解码头直接预测多 token，免草稿模型。 |
| ⭐ **Prefill/Decode 分离（Disaggregation）** | Prefill（算力密集）与 Decode（显存密集）拆到不同节点池，各自最优扩缩容；DistServe/SplitWise 论文。 |
| ⭐ **Chunked Prefill** | 长 prompt 切块与解码请求混批，平衡首 token 延迟与吞吐。 |
| ⭐ **TTFT / TPOT / ITL** | 首 token 延迟 / 每 token 延迟 / token 间延迟；流式体验的核心指标，p50/p99 都要看。 |
| **吞吐 vs 延迟权衡** | 大 batch 吞吐高但单请求延迟高；SLA 决定运行点，在线服务偏延迟、离线偏吞吐。 |
| ⭐ **批处理 API（Batch API）** | 异步提交、24h 返回、半价；适合离线评测/数据处理，省钱 50%。 |
| ⭐ **模型蒸馏部署** | 用蒸馏小模型承接高频简单任务（分类/抽取），大模型只处理难题，成本降一个数量级。 |

## 9. 提示词工程

| 术语 | 释义 |
|------|------|
| ⭐ **提示词工程（Prompt Engineering）** | 通过设计输入指令引导模型产生期望输出的技术；零成本迭代，是应用开发第一道杠杆。 |
| ⭐ **Zero-shot / Few-shot** | 不给示例直接提问 / 在提示中给少量输入-输出示例；示例选择与顺序显著影响效果。 |
| ⭐ **思维链（Chain-of-Thought, CoT）** | 引导模型"分步推理"再给结论，数学/逻辑题大幅提分；推理模型已把 CoT 内化成长思维链。 |
| ⭐ **ReAct** | Reason + Act 交替：思考→工具调用→观察→再思考；Agent 循环的经典范式。 |
| **Self-Consistency（自洽性）** | 采样多条推理路径，对答案多数投票；数学题提分利器，成本 ×n。 |
| ⭐ **角色设定（Persona/Role）** | system prompt 中设定专家角色与约束；提升专业性与风格一致性。 |
| ⭐ **分隔符与结构化** | 用 ```/XML 标签隔离指令与数据，防注入、利解析；结构化模板比自然语言段落稳定。 |
| ⭐ **提示词注入（Prompt Injection）** | 攻击者把恶意指令藏进数据（网页/邮件/工具返回）劫持模型；Agent 时代头号安全威胁。 |
| 🔬 **间接注入（Indirect Injection）** | 注入经工具/RAG 文档进入上下文，模型可能被诱导泄密或调危险工具；靠数据隔离/最小权限/输出校验。 |
| ⭐ **上下文学习（ICL, In-Context Learning）** | 不更新权重，仅靠提示中的示例/说明完成任务；涌现能力的代表。 |
| ⭐ **温度 / Top-p 调参** | 事实任务低温（0–0.3），创作任务高温（0.7–1）；结构化抽取用 0 + schema 约束。 |
| **元提示 / 提示词模板** | 可复用的参数化提示（变量槽位）；版本化管理，纳入 Eval 门禁。 |
| **DSPy / 自动优化提示** | 把提示当作可编译程序，用优化器自动搜索 few-shot 与指令；提示工程自动化方向。 |
| 🆕 **上下文工程（Context Engineering）** | Agent 时代的升级概念：系统管理进入上下文的信息（记忆、工具结果、摘要、引用句柄），而非只写单条提示。 |

## 10. 检索增强生成（RAG）

| 术语 | 释义 |
|------|------|
| ⭐ **RAG（检索增强生成）** | 先从知识库检索相关文档，再让模型基于文档回答；解决知识过时、幻觉、私有数据接入三大问题。 |
| ⭐ **Embedding / 向量化** | 文本 → 稠密向量，语义相近则向量相近；检索的语义基础。 |
| ⭐ **向量数据库** | 存储 embedding 并做 ANN 检索：Milvus/Qdrant/Weaviate/pgvector；选型见 Special-03。 |
| ⭐ **ANN（近似最近邻）** | HNSW/IVF 等索引把暴力 O(n) 检索降到亚线性；召回率与速度权衡。 |
| ⭐ **Chunking（分块）** | 文档切成检索单元：固定大小 + overlap、按结构（标题/段落）、语义切分；块大小是 RAG 第一超参。 |
| ⭐ **两阶段检索（召回 + 精排）** | 粗：向量/关键词召回 top-20~100；精：Cross-encoder Reranker 排到 top-3~5。 |
| ⭐ **混合检索（Hybrid Search）** | 向量检索（语义）+ BM25/关键词（精确术语/数字/专有名词）融合；实战中几乎必开。 |
| ⭐ **Reranker（重排序）** | Cross-encoder 对 query-chunk 对联合编码精排，比 bi-encoder 准；BGE-Reranker/Cohere Rerank。 |
| ⭐ **HyDE** | 先让模型生成假设性答案，用它去检索；缓解 query 短、与文档表述不匹配的问题。 |
| **查询改写 / 多查询（Multi-Query）** | 把用户问题改写/扩展成多个子查询分别检索再融合；处理模糊与复杂问题。 |
| ⭐ **句子窗口 / 自动合并检索** | 检索小块（精确）但返回其所在大块/父文档（上下文完整）；LlamaIndex 经典进阶技法。 |
| ⭐ **GraphRAG 🆕** | 知识图谱 + 社区摘要，擅长全局性问题（"总结整个语料的主题"）；微软提出，向量 RAG 的补充而非替代。 |
| 🆕 **Agentic RAG** | 由 Agent 自主决定"要不要检索、检索什么、结果够不够、是否再查"；RAG 从固定管线变成可推理循环。 |
| ⭐ **RAGAS 评测指标** | Faithfulness（忠实度/答案是否有据）、Answer Relevancy、Context Precision/Recall；RAG 自动化评测标准。 |
| **引用与归因（Citation）** | 回答标注来源片段；可核验、降幻觉、合规要求高的行业必备。 |
| **索引更新 / 增量同步** | 文档变更的增删改同步策略；权限过滤必须在检索阶段（行级 ACL），不能事后过滤。 |

## 11. 智能体（Agent）与工具调用

| 术语 | 释义 |
|------|------|
| ⭐ **AI Agent（智能体）** | 能自主感知-规划-行动-反思，用工具完成多步任务的 LLM 系统；核心 = LLM + 工具 + 记忆 + 循环。 |
| ⭐ **Agent Loop（智能体循环）** | 推理→调工具→观察结果→再推理，直到任务完成；ReAct 是其经典实现。 |
| ⭐ **Function Calling（函数调用）** | 模型输出结构化工具调用（名称 + JSON 参数），运行时执行后回灌；Agent 行动的原子能力。 |
| ⭐ **工具（Tool）** | Agent 可调用的能力：API、函数、代码执行、MCP Server；需名称、描述、JSON Schema 参数。 |
| ⭐ **MCP（模型上下文协议）** | Anthropic 发起、2025 年成行业标准的"Agent↔工具/数据"协议；Streamable HTTP + OAuth 2.1 + Registry。详见 Special-06。 |
| **MCP Server / Client / Host** | Server 暴露 Tools/Resources/Prompts；Client 维持连接；Host 是承载 Agent 的应用。 |
| ⭐ **规划（Planning）** | 任务分解与步骤编排；简单任务 ReAct 即够，复杂任务用 Plan-and-Execute 或主管 Agent。 |
| ⭐ **记忆（Memory）** | 短期：对话上下文；长期：跨会话的向量记忆/知识；工作记忆靠检查点持久化。 |
| ⭐ **多智能体（Multi-Agent）** | 多个专长 Agent 协作：Supervisor（主管分派）、Handoff（流水线交接）、Swarm（对等/A2A）。 |
| ⭐ **A2A（Agent2Agent 协议）** 🆕 | Google 发起、Linux Foundation 托管的 Agent 间通信协议；Agent Card 发现 + Task 生命周期，用于跨组织 Agent 协作。 |
| ⭐ **HITL（Human-in-the-Loop，人机协作）** | 高危动作审批、信息补全、人工接管；Run 挂起持久化、审批后恢复是工程关键。 |
| 🧭 **Durable Execution（持久化执行）** | 运行状态外置为检查点/事件日志，Worker 可随时崩溃恢复；Temporal/LangGraph Checkpointer 思想。 |
| ⭐ **沙箱（Sandbox）** | 隔离执行不可信代码/工具的环境：microVM（Firecracker）/gVisor/容器；一次性、最小权限。 |
| ⭐ **护栏（Guardrails）** | 输入过滤、权限校验、输出 schema 校验、敏感信息扫描；Agent 安全的纵深防线。 |
| **幂等键（Idempotency Key）** | 让重试不产生重复副作用的唯一键；Agent 工具调用与分布式系统的地基。 |
| ⭐ **Token/成本预算** | 单任务 max_steps/max_cost/max_time 三重护栏，防 Agent 死循环烧钱。 |
| **Skill / 技能** | 把可复用流程（指令 + 脚本 + 资源）打包成 Agent 可加载的能力单元；Codex Skills、百炼 Skill 同概念。 |
| **Computer Use / 浏览器 Agent** 🆕 | Agent 直接操作 GUI（点击/输入/截屏）；Claude Computer Use、OpenAI Operator 类，可靠性仍是前沿。 |

## 12. 多模态大模型

| 术语 | 释义 |
|------|------|
| ⭐ **多模态（Multimodal）** | 同时处理文本、图像、音频、视频；大模型从"读文字"走向"看听说"。 |
| ⭐ **CLIP** | OpenAI 图文对比学习模型：图像与文本映射到同一向量空间，奠定图文检索/视觉理解基础。 |
| ⭐ **视觉编码器（Vision Encoder）** | ViT 等把图像编码为 embedding；多模态 LLM 用它把视觉特征接入语言模型。 |
| ⭐ **LLaVA 架构** | 视觉编码器 + 投影层（MLP/Q-Former）+ LLM 的经典多模态对话架构；开源 VLM 范式。 |
| **Q-Former / 投影层** | 把变长视觉特征压缩/对齐为 LLM 可消费的 token 序列。 |
| ⭐ **VLM（视觉语言模型）** | GPT-4V/Gemini/Qwen-VL/InternVL；支持图文理解、文档 OCR、图表解读。 |
| **OCR / 文档理解** | 文字识别 + 版面理解；发票、合同、报表场景的刚需能力。 |
| ⭐ **文生图（Text-to-Image）** | Diffusion 扩散模型：DALL·E/Stable Diffusion/FLUX；通过去噪过程生成图像。 |
| 🔬 **扩散模型（Diffusion）** | 前向加噪、反向去噪学习生成；Latent Diffusion 在潜空间做以降算力；现代图像/视频生成基础。 |
| ⭐ **DiT（Diffusion Transformer）** | 用 Transformer 替代 U-Net 做扩散骨干；Sora 类视频生成模型架构。 |
| 🆕 **文生视频（Text-to-Video）** | Sora/可灵/即梦/Veo；时序一致性、算力成本是核心挑战。 |
| **语音：ASR/TTS/语音对话** | 语音识别（Whisper）、语音合成、端到端语音模型（GPT-4o 实时语音）；延迟是体验关键。 |
| **统一多模态模型** | Gemini/GPT-4o 类：原生混合处理多模态输入输出（Omni 模型），而非拼装。 |

## 13. 评估、可观测性与 MLOps

| 术语 | 释义 |
|------|------|
| ⭐ **MLOps / LLMOps** | 机器学习/大模型系统的工程化与运维：数据、训练、部署、监控、回滚的流水线化。 |
| ⭐ **模型评估（Evaluation）** | 离线基准 + 在线指标；大模型评估从"答题准确率"扩展到任务成功率与轨迹质量。 |
| ⭐ **基准测试（Benchmark）** | MMLU（知识）、GSM8K/MATH（数学）、HumanEval/SWE-bench（代码）、C-Eval/CMMLU（中文）。 |
| 🆕 **Agent 评估** | τ-bench（工具调用轨迹/终态）、AgentBench、WebArena；评"任务是否完成、工具是否用对"。 |
| ⭐ **LLM-as-Judge** | 用强模型按 rubric 给输出打分；便宜可扩展，需与人工标注校准（一致率 >85%）。 |
| ⭐ **人工评估（Human Eval）** | 标注员偏好/质量打分；金标准但贵慢，用于校准自动评估。 |
| ⭐ **A/B 测试 / 金丝雀** | 线上分流对比版本；按租户随机、看任务成功率/成本/升级率，自动灰度回滚。 |
| ⭐ **影子流量（Shadow）** | 复制线上流量到新版本但不产生副作用；Agent 变更零风险验证。 |
| ⭐ **可观测性三支柱** | Metrics（指标）、Logging（日志）、Tracing（链路追踪）；LLM 系统加"Prompt/Completion 观测"。 |
| ⭐ **Trace / Span** | 一次 Agent Run 的完整调用树：LLM 调用、工具调用、审批、成本；Langfuse/Phoenix/OTel GenAI。 |
| **Token 用量 / 成本监控** | 按租户/模型/Agent 归因 token 与花费；预算告警是平台核心功能。 |
| ⭐ **数据漂移 / 模型衰减** | 数据分布变化使模型效果退化；LLM 应用靠持续 eval + badcase 回流监控。 |
| ⭐ **模型版本 / 注册表（Registry）** | 模型、prompt、路由策略全部版本化、可回滚；Agent 的"代码"也需版本管理。 |
| **CI/CD for ML** | 数据/模型/prompt 变更触发测试、eval 门禁、灰度发布；Eval 是 Agent 的单元测试。 |
| **RAGAS / 深度评估** | RAG 专用指标库；端到端评估忠实度、相关性、上下文质量。 |
| **在线反馈闭环** | 用户点踩/点赞/改写 → badcase 队列 → 标注 → 数据飞轮。 |

## 14. AI 安全、伦理与合规

| 术语 | 释义 |
|------|------|
| ⭐ **对齐 3H** | Helpful（有用）、Harmless（无害）、Honest（诚实）；对齐的三大目标。 |
| ⭐ **幻觉治理** | RAG 接地、引用来源、输出校验、温度控制、置信度提示；无法根除只能缓解。 |
| ⭐ **数据隐私** | 训练/日志中的 PII 脱敏；客户数据不入训练；合规（GDPR/个保法）。 |
| ⭐ **偏见与公平性（Bias/Fairness）** | 训练数据偏见导致群体歧视；用多样数据、公平性指标、审计缓解。 |
| **可解释性（XAI）** | 特征归因（SHAP/LIME/Integrated Gradients）；大模型时代转向行为级解释（引用、推理链）。 |
| ⭐ **对抗攻击（Adversarial Attack）** | 输入微小扰动致模型误判；CV 领域经典，LLM 时代对应越狱/注入。 |
| **越狱 / 提示注入** | 见第 9 节；Agent 工具权限使其风险升级为"真实世界动作"。 |
| **深度伪造（Deepfake）** | AI 生成虚假音视频；内容溯源（水印/C2PA）与检测是治理方向。 |
| ⭐ **AI 水印（Watermark）** | 在生成内容中嵌入可检测信号；文本水印（token 概率偏置）与图像水印。 |
| **合规认证** | SOC 2、ISO 27001、等保（中国）、行业法规（金融/医疗）；企业落地准入门槛。 |
| **负责任 AI（Responsible AI）** | 覆盖公平、透明、问责、安全、隐私的治理框架；企业级 AI 的制度层。 |

## 15. AI 产品、业务与成本

| 术语 | 释义 |
|------|------|
| ⭐ **PoC（概念验证）** | 小规模验证可行性与价值；AI 项目 PoC 目标是"证真或证伪"，周期 2–6 周，勿做成小生产。 |
| ⭐ **AI 适用性评估** | 用"模式识别强度 × 数据就绪 × 容错空间 × ROI"判断该不该上 AI；不是所有问题都该用 AI。 |
| ⭐ **ROI（投资回报）** | AI 项目收益 = 人力节省 + 体验提升 + 新增收入；成本 = 算力 + 开发 + 运维 + 试错。 |
| ⭐ **TCO（总拥有成本）** | 不只是 token 费：GPU、人力、集成、数据治理、失败重试都要算。 |
| ⭐ **人机回环设计** | 产品上把"AI 做 80%、人审关键 20%"产品化；审批 UI、置信度展示、一键接管。 |
| **AI 原生 vs AI 增强** | 原生：交互范式为对话/Agent 重构；增强：传统流程里插一个 AI 点；产品设计思路不同。 |
| ⭐ **token 定价 / 加价模式** | 按 in/out token 计费；平台在到岸成本上加价 5%–15%（OpenRouter 模式）。 |
| ⭐ **GPU 利用率** | 自托管推理的核心经济指标：>40%–60% 利用率时自托管才比 API 划算。 |
| **FinOps for AI** | 预算、归因（showback/chargeback）、省钱策略（缓存/小模型路由/批处理）一整套成本治理。 |
| **多租户（Multi-tenancy）** | 共享平台服务多客户：逻辑隔离（行级权限）到物理隔离（VPC/私有化）分级。 |
| **SLA / SLO** | 服务承诺与目标：可用性 99.9%、TTFT、失败率；错误预算指导发版节奏。 |

## 16. 2024–2026 前沿术语

| 术语 | 释义 |
|------|------|
| 🆕⭐ **推理模型（Reasoning Model）** | o1/o3、DeepSeek-R1、Qwen QwQ：用长思维链 + RLVR 训练，擅长数学/代码/复杂规划；思考过程可见可区分。 |
| 🆕⭐ **测试时计算（Test-time Compute）** | 推理时投入更多算力（长 CoT、多次采样、树搜索）换性能；与训练时 scaling 互补的新 scaling 维度。 |
| 🆕 **RLVR（可验证奖励 RL）** | 奖励由规则判定（答案对、单测过、格式合法），无需人类偏好标注；推理能力突破的关键。 |
| 🆕 **思维链长度 / 思考预算** | 推理模型用 token 数换正确率；可按任务难度调节"思考预算"平衡成本与质量。 |
| 🆕⭐ **Agentic Coding（智能体编程）** | Claude Code/Codex/Cursor Agent 等：Agent 自主读库、改码、跑测试、提 PR；软件开发范式从补全走向委派。 |
| 🆕 **长上下文（Long Context）** | 128k–1M token 窗口；整库/整书塞入，但"大海捞针"可靠性与成本仍需 RAG 配合。 |
| 🆕 **SLM（小语言模型）** | 1B–8B 级模型（Phi/Qwen 小尺寸/Llama 轻量）：端侧、高并发、低成本场景；蒸馏 + 专精训练逼近大模型特定任务。 |
| 🆕 **端侧 AI（On-device）** | 手机/PC 本地跑模型（Apple Intelligence、高通 NPU）；隐私、低延迟、离线可用。 |
| 🆕 **合成数据（Synthetic Data）** | 用强模型/规则生成训练数据：指令、推理链、多语种；质量过滤与多样性是关键，防"模型近亲繁殖"。 |
| 🆕 **模型坍塌（Model Collapse）** | 长期用 AI 生成数据训练 AI 导致分布退化、多样性丧失；数据来源治理的隐忧。 |
| 🆕 **世界模型（World Model）** | 学习环境动态、能预测行动后果的模型；Yann LeCun 主张的方向，视频生成与具身智能交叉。 |
| 🆕 **具身智能（Embodied AI）** | LLM/VLM 作为机器人大脑（VLA 模型）；感知-决策-执行落到物理世界。 |
| 🆕 **VLA（Vision-Language-Action）** | 视觉-语言-动作模型，机器人控制新范式（RT-2、π0、GR00T）。 |
| 🆕 **AI 浏览器 / Computer Use** | Operator/Comet 类 Agent 直接操作网页/GUI 完成任务；RPA 的 AI 原生升级。 |
| 🆕 **MCP / A2A 生态** | 见第 11 节；2025 年工具互联与 Agent 互联标准化，平台必须跟进。 |
| 🆕 **AI 编程的 Skills/Plugins** | 把领域流程打包为可复用技能包（Codex Skills、Claude Plugins）；能力复用与分发的新单元。 |
| 🆕 **推理-路由（Reasoning Routing）** | 平台按任务难度自动选择：简单任务用小/快模型，难题用推理模型；成本-质量智能调度。 |

## 附：易混概念速辨

| 易混对 | 区别一句话 |
|--------|-----------|
| 预训练 vs 微调 | 预训练学通用知识（无标签、万亿 token），微调学任务/风格（有标签、万级样本）。 |
| SFT vs RLHF | SFT 教模型"怎么答"（模仿示范），RLHF 教模型"怎么选更好"（偏好优化）。 |
| LoRA vs QLoRA | LoRA 训练低秩适配器；QLoRA 先把基座 4bit 量化再训 LoRA，省显存。 |
| DPO vs PPO | PPO 用奖励模型 + RL 在线优化；DPO 直接用成对数据做离线优化，简单稳定。 |
| 数据并行 vs 张量并行 | 数据并行切数据（模型复制）；张量并行切单层权重（模型拆分）。 |
| 量化 vs 蒸馏 | 量化减数值精度（不改结构）；蒸馏用大学生教小学生（改模型规模）。 |
| RAG vs 微调 | RAG 注入"可查的知识"（热更新、可溯源）；微调注入"行为/风格/技能"（内化但难更新）。 |
| Embedding vs Reranker | Embedding 是双塔（快、粗召回）；Reranker 是交叉编码（慢、精排）。 |
| Agent vs 工作流 | 工作流路径预先固定；Agent 的下一步由模型动态决定（自治度更高、更不可控）。 |
| MCP vs A2A | MCP 是 Agent 连工具；A2A 是 Agent 连 Agent。 |
| TTFT vs TPOT | TTFT 是等首字的时间（感知"响应了没"）；TPOT 是之后每字速度（感知"流得快不快"）。 |
| 准确率 vs 忠实度 | 准确率看答案对不对；忠实度看答案是否基于给定上下文（RAG 核心，防幻觉）。 |
| 幻觉 vs 拒答 | 幻觉是编造内容；过度拒答是该答不答；两者是安全-有用天平的两端。 |
